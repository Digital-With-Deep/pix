A2UI (Agent-to-User Interface) is an open protocol for agent-generated interfaces. An agent sends a stream of JSON messages that describe a surface, its components and its data, and the app renders them with its own design system. `@pix-ui/a2ui` makes PIX that design system: it ships a PIX catalog the agent generates against, and a React renderer that turns the message stream into PIX components and reports clicks, approvals and rejections back as A2UI action messages.

This package targets A2UI protocol version 1.0 (`"version": "1.0"` on every message).

```sh
npm i @pix-ui/a2ui @pix-ui/react
```

## The PIX catalog

A catalog is the list of components and functions an agent may use, written as JSON Schema. The PIX catalog id is:

```text
https://pixui.digitalwithdeep.com/a2ui/catalogs/pix/v1/catalog.json
```

The id is an identifier the agent and the renderer agree on, not an address the renderer fetches. The catalog definition ships with the package, so you can put it in the agent's prompt and validate generated messages against it:

```js
import catalog from "@pix-ui/a2ui/catalog.json" with { type: "json" };
import { PIX_CATALOG_ID, pixCatalog, rendererCapabilities } from "@pix-ui/a2ui";

// Tell the agent which catalogs this renderer supports, in your transport's metadata.
const a2uiRendererCapabilities = rendererCapabilities();
// { "1.0": { supportedCatalogIds: ["https://pixui.digitalwithdeep.com/a2ui/catalogs/pix/v1/catalog.json"] } }
```

The catalog's `instructions` field carries PIX guidance for the model: lay out with Column and Row, ask for approval before any action that spends money or cannot be undone, and bind changing values to the data model.

## Supported components

| A2UI component | Renders | Properties |
| --- | --- | --- |
| `Column`, `Row` | `Stack` | `children`, `gap`, `align`, `justify`; `Row` also `wrap` |
| `Grid` | `Grid` | `children`, `min`, `cols`, `gap` |
| `Card` | `pix-card` surface | `child` |
| `Divider` | Rule | none |
| `Text` | Plain text | `text`, `variant` (`body`, `caption`, `heading`, `label`, `code`) |
| `Markdown` | `Markdown` | `text`, `streaming` |
| `Button` | `Button` | `label` or `child`, `variant`, `size`, `disabled`, `action`, `@checks` |
| `Badge` | `Badge` | `text`, `tone`, `dot`, `size` |
| `Callout` | `Callout` | `title`, `body`, `tone`, `compact` |
| `Alert` | `Alert` | `title`, `body`, `tone`, `citation`, `actions` |
| `MetricCard` | `MetricCard` | `label`, `value`, `delta`, `deltaType`, `hint`, `valueTone`, `progress` |
| `DataTable` | `DataTable` | `columns`, `rows`, `caption`, `searchable`, `emptyMessage`, `rowAction` |
| `AIResponse` | `AIResponse` | `text`, `status`, `model`, `duration`, `tokens`, `stage`, `error`, `thinking`, `citations`, `stopAction`, `retryAction`, `feedbackAction` |
| `ToolCall` | `ToolCall` | `name`, `status`, `description`, `input`, `output`, `error`, `duration`, `child`, `retryAction` |
| `ApprovalCard` | `ApprovalCard` | `title`, `summary`, `agent`, `target`, `reason`, `changes`, `risk`, `reversible`, `evidence`, `expiresAt`, `status`, `decidedBy`, `decidedAt`, `rejectReason`, `requireRejectReason`, `approveLabel`, `approveAction`, `rejectAction`, `editAction` |
| `Conversation` | `Conversation` | `messages`, `children`, `label`, `height` |

Most text, number and boolean properties accept a literal, a data binding such as `{"@path": "/order/id"}` or a function call such as `{"@call": "formatString", ...}`. Paths are JSON Pointers, as defined in RFC (Request for Comments) 6901. Inside a list template (`children` set to `componentId` and `path`), a path without a leading slash is relative to the current item, and `@index` gives its position.

`ApprovalCard` calls the proposed action `summary`, because in A2UI the name `action` is reserved for what a press does. The catalog also provides `formatString`, `formatNumber`, `formatCurrency`, `required`, `and`, `or` and `not`.

## A minimal agent message stream

An agent creates a surface on the PIX catalog with its components and data in one message, then streams changes to the data. Each line is one message:

```json
{"version": "1.0", "createSurface": {"surfaceId": "refund_review", "catalogId": "https://pixui.digitalwithdeep.com/a2ui/catalogs/pix/v1/catalog.json", "dataModel": {"order": {"id": "ORD-20417", "total": 184.5}, "approval": {"status": "pending"}}, "components": [
  {"id": "root", "component": "Column", "children": ["title", "refund"]},
  {"id": "title", "component": "Text", "variant": "heading", "text": {"@call": "formatString", "args": {"value": "Refund review for ${/order/id}"}}},
  {"id": "refund", "component": "ApprovalCard", "title": "Issue a refund", "summary": "Refund the full order to the original payment method.", "agent": "support-agent", "target": {"@path": "/order/id"}, "risk": "high", "reversible": false,
   "status": {"@path": "/approval/status"},
   "approveAction": {"event": {"name": "refund.approve", "context": {"orderId": {"@path": "/order/id"}, "amount": {"@path": "/order/total"}}}},
   "rejectAction": {"event": {"name": "refund.reject", "context": {"orderId": {"@path": "/order/id"}}}}}
]}}
{"version": "1.0", "updateDataModel": {"surfaceId": "refund_review", "path": "/order/total", "value": 172.0}}
```

The renderer also handles `updateComponents` (add or replace components by id) and `deleteSurface`. Components can arrive in any order; nothing renders until the component with id `root` exists, and a missing child renders as nothing until it arrives.

## Render a surface and wire onAction

Pass the messages in arrival order, adding new ones at the end as they stream. If the earlier messages change, the renderer starts over from the new list.

```jsx
import "@pix-ui/react/styles.css";
import { A2UISurface } from "@pix-ui/a2ui";

export function AgentPanel({ messages, sendToAgent, reportToAgent }) {
  return (
    <A2UISurface
      messages={messages}
      onAction={(message, metadata) => sendToAgent(message, metadata)}
      onError={(message) => reportToAgent(message)}
    />
  );
}
```

When the reviewer approves, `onAction` receives the A2UI action message, with every binding in the context resolved:

```json
{
  "version": "1.0",
  "action": {
    "name": "refund.approve",
    "surfaceId": "refund_review",
    "sourceComponentId": "refund",
    "timestamp": "2026-11-22T15:04:05.000Z",
    "context": { "orderId": "ORD-20417", "amount": 172 }
  }
}
```

Send it to the agent over your transport, for example AG-UI (Agent-User Interaction protocol), A2A (Agent-to-Agent protocol) or MCP (Model Context Protocol). The renderer adds a few keys to the context itself:

- `rejectAction`: `reason`, the text the reviewer gave, or `null`.
- `editAction`: `edits`, an object of change key to new value.
- `feedbackAction` on `AIResponse`: `vote`, `"up"`, `"down"` or `null`.
- `rowAction` on `DataTable`: `row`, the clicked row.

When `status` on an `ApprovalCard` is bound to the data model, the renderer writes `approved` or `rejected` there as soon as the reviewer decides, so the card shows the outcome at once. Treat that as a display state: the agent acts on the action message, and its next `updateDataModel` has the last word.

If the surface was created with `sendDataModel: true`, the second argument to `onAction` holds `a2uiRendererDataModel`, the surface's whole data model, to put in your transport's metadata.

`onError` receives renderer-to-agent error messages, for example `INTEGRITY_ERROR` for a duplicate `createSurface` or `VALIDATION_FAILED` for an unknown component type. Errors found while rendering are delivered after the render commits.

## Live streams and your own catalogs

For a live stream, create a processor and feed it yourself:

```jsx
import { A2UISurface, createA2UIProcessor, PIX_CATALOG_ID } from "@pix-ui/a2ui";

const processor = createA2UIProcessor({ catalogIds: [PIX_CATALOG_ID], onError: reportToAgent });
socket.onmessage = (event) => processor.process(JSON.parse(event.data));

<A2UISurface processor={processor} onAction={sendToAgent} />;
```

A surface can mix catalogs: a component with `@catalogId` resolves against that catalog instead of the surface default. Add your own with `defineCatalog(catalogId, components)` and pass it with the PIX catalog in `catalogs`.

## What is not supported yet

- The basic catalog's input components (`TextField`, `CheckBox`, `ChoicePicker`, `Slider`, `DateTimeInput`) and its `Image`, `Icon`, `Video`, `AudioPlayer`, `List`, `Tabs` and `Modal`. The PIX catalog does not claim the basic catalog id.
- Agent-side functions. A function call the renderer cannot run resolves to `null` and reports `EXPRESSION_ERROR`, instead of being sent to the agent as `callAgentFunction`.
- Agent calls to renderer functions. Every PIX catalog function is renderer-only, so `callRendererFunction` gets an `INVALID_FUNCTION_CALL` reply through `onFunctionResponse`.
- `allowedParents` and `allowedChildren` checks. The PIX catalog sets none.

## Security

Agent output is untrusted. The renderer only renders components from catalogs you pass, never raw HTML; Markdown is rendered without HTML; and links in `citations` and `evidence` are limited to `http`, `https`, `mailto` and relative addresses.
