Buttons let a user trigger an action or navigate to a next step. Pick a variant that matches how important the action is relative to everything else on the screen.

## When to use

- To submit a form, run a job, or confirm a decision.
- To let a user cancel, dismiss, or back out of a flow.
- To trigger a destructive action, paired with the `destructive` variant and ideally a confirmation step.
- Prefer a link when the action is primarily navigation rather than a state change.

## Variants

`primary` is the default solid button for the most common action on a screen. `filled` is a dedicated "go" action, such as kicking off a run. `secondary` and `outline` sit a level below for supporting actions, `destructive` flags irreversible actions like deleting a run, and `ghost` is the quietest option for low-emphasis actions like "Details" inside a row.

## Sizes

`sm`, `md` (the default), and `lg` scale padding, font size, and icon size together. Use `sm` inside dense rows like tables, and `lg` for a single standalone call to action.

## States

Set `loading` while an action is in flight. The leading icon, if any, is replaced with a spinner, the label can be swapped with `loadingLabel`, and the button stops accepting clicks. Set `disabled` when the action isn't currently available — for example, until a required field is filled in.

## Anatomy

A button is a label, an optional leading icon, and a visual treatment:

- `variant` — one of `primary`, `filled`, `secondary`, `outline`, `destructive`, `ghost`.
- `size` — one of `sm`, `md`, `lg`.
- `iconPath` — an SVG path `d` string rendered as a leading, 2px-stroke outline icon. Omit `children` entirely to get a square icon-only button.
- `loading` / `loadingLabel` — shows a spinner in place of the icon and blocks interaction while an action runs.
- `disabled` — blocks interaction and lowers opacity.

## Accessibility

- The underlying element is a native `<button type="button">`, so it's keyboard-reachable and activates with `Enter` and `Space` without extra wiring.
- While `loading`, the button sets `aria-busy="true"` and is disabled so a screen reader announces the busy state and a stray click can't double-submit.
- An icon-only button (no `children`) has no visible label — pass `aria-label` so assistive technology has something to announce.
- `disabled` removes the button from the tab order; don't rely on it alone to explain *why* an action is unavailable — pair it with visible context nearby.
